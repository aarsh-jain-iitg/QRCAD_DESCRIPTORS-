# CAD Retrieval System — Current Technical State

## Overview

Training-free, CPU-only 3D CAD shape retrieval pipeline. No labeled data, no GPU, no learned parameters in any stage. Given a query mesh, produces ranked top-K similar models from a pre-indexed repository. Sub-millisecond query time at 600 models.

**Full title:** *An Explainable Training-Free CAD Retrieval Framework Using Multi-View Density Occupancy Representation and Multi-Modal Shape Descriptors*
**Authors:** K. Venkata Gowtham Royal, Aarsh Jain, Dr. Sajan Kapil — IIT Guwahati
**Status:** Unpublished

## Pipeline — Stage by Stage

### Stage 1: Normalization

**Input:** Raw triangular mesh (STL/STEP/OBJ). Vertex set $\mathcal{V} = \{v_1, v_2, \ldots, v_N\}$.

**Step 1 — Centroid translation:**
$$c = \frac{1}{N} \sum_{i=1}^{N} v_i, \qquad v_i' = v_i - c$$

**Step 2 — Scale normalization:**
$$s = \max(\Delta x, \Delta y, \Delta z), \qquad v_i'' = v_i' / s$$

Largest bounding box dimension becomes 1. Every model is brought to the unit cube before alignment. This is essential for D1 and D2 because raw Euclidean distances would otherwise reflect physical size rather than shape; HOG gradient magnitudes also depend on consistent density map scale.

---

### Stage 2: PCA Alignment

Covariance matrix of centered, scaled vertices:
$$C = \frac{1}{N} \sum_{i=1}^{N} (v_i - c)(v_i - c)^\top, \qquad C = Q \Lambda Q^\top$$

Rotation matrix $R = [e_1\ e_2\ e_3]$ from the three principal eigenvectors (columns ordered by descending eigenvalue). Aligned vertices:
$$\mathcal{V}_\text{aligned} = R\mathcal{V}$$

Primary axis of variation → X-axis. Secondary → Y. Tertiary → Z. Makes slicing viewpoint-consistent across the entire repository.

**Known flaw:** Eigenvalue-ordered axis assignment is unstable when two eigenvalues are close (near-symmetric objects: thin-walled boxes, hollow cylinders with matched moments of inertia). A small mesh perturbation can swap two axes, producing a different descriptor vector for the same physical object.

---

### Stage 3: Orthogonal Multi-View Slicing (MDOR Generation)

For $N = 100$ slices along the X-axis, slice positions:
$$\Delta x = \frac{x_\text{max} - x_\text{min}}{N}, \qquad x_k = x_\text{min} + k\Delta x, \quad k = 0, \ldots, N-1$$

Same procedure along Y and Z. At each slice position $k$, a binary occupancy image $S_k(u, v)$ of resolution $128 \times 128$ pixels is generated by projecting the slice geometry onto the plane orthogonal to the slicing axis.

**MDOR accumulation and normalization:**
$$D(u, v) = \sum_{k=1}^{N} S_k(u, v), \qquad D_n(u, v) = \frac{D(u, v)}{N}$$

$$\text{MDOR} = \{D_X,\ D_Y,\ D_Z\}$$

Each $D_n(u,v) \in [0, 1]$; high values indicate spatial locations occupied across many slices (solid interior regions). Unlike depth maps (nearest surface only) or silhouettes (boundary only), MDOR encodes full volumetric thickness along each projection direction.

**Hyperparameters:**
- Slices per axis: $N = 100$ (saturation point; gains flatten between $N=100$ and empirical peak at $N=140$, within run-to-run variance)
- Density map resolution: $128 \times 128$ pixels
- Slice spacing and pixel pitch are comparable at $N=100$: $L_\text{max}/100$ vs $L_\text{max}/128$, which explains why further increasing $N$ adds no discriminative information

**Feature resolution floor:** One pixel spans $L_\text{max}/128$ of the model's largest bounding-box dimension. For a 1 m model, $\delta_\text{pixel} \approx 7.8$ mm. HOG operates on $16 \times 16$ pixel cells, so in practice features must span $\geq 2$–3 pixels ($\gtrsim 15$–25 mm at 1 m scale) to survive cell-level gradient aggregation. Features smaller than this are invisible to the pipeline.

---

### Stage 4: HOG Feature Extraction

Applied independently to $D_X$, $D_Y$, $D_Z$.

**Gradient computation (central differences):**
$$G_x = D(u+1, v) - D(u-1, v)$$
$$G_y = D(u, v+1) - D(u, v-1)$$
$$M(u,v) = \sqrt{G_x^2 + G_y^2}, \qquad \theta(u,v) = \arctan(G_y / G_x)$$

**Cell histograms:**
- Cell size: $16 \times 16$ pixels
- 9 orientation bins, $0°$–$180°$ (unsigned — dark-to-bright and bright-to-dark at the same boundary are geometrically equivalent edge events)
- Each gradient weighted by magnitude $M(u,v)$

**Block normalization:**
- Block size: $2 \times 2$ cells = $32 \times 32$ pixels
- Block stride: 16 pixels (overlapping blocks)
- 4 cell histograms per block concatenated → L2-normalized → block descriptor $h_{b_k} \in \mathbb{R}^{36}$

**Descriptor dimensions:**
- $128 \times 128$ map, $16 \times 16$ cells, stride 16 → $B = 49$ blocks per view
- Per-view HOG: $49 \times 36 = 1764$ dimensions
- Three views concatenated: $F_\text{HOG} = [F^X_\text{HOG},\ F^Y_\text{HOG},\ F^Z_\text{HOG}] \in \mathbb{R}^{5292}$

**Why $16 \times 16$ cells:** Smaller cells ($8 \times 8$) → too few pixels per bin → noisy histograms. Larger cells ($32 \times 32$) → averages away fine boundary transitions (gear teeth, castle nut slots) that HOG is meant to capture.

---

### Stage 5: D1 Shape Descriptor

Characterizes global radial mass distribution.

$$d_i = \|p_i - c\|, \qquad F_{D1} = \text{histogram}(d_i)$$

- $K = 10^5$ surface points $p_i$ sampled using area-weighted triangle sampling
- 64-bin histogram over $[0, r_\text{max}]$ where $r_\text{max}$ is the circumradius of the unit-normalized model
- Bin $b_k$ accumulates points with centroid distance in $[k \cdot r_\text{max}/64,\ (k+1) \cdot r_\text{max}/64)$
- L1-normalized to sum to unity → independent of sample count
- $F_{D1} \in \mathbb{R}^{64}$

**What D1 captures:** Solid sphere → unimodal peak at radius. Hollow cylinder → bimodal with near-zero trough at small distances, sharp peak near shell radius. Directly discriminates solid shaft from hollow tube of same outer diameter.

**Stochastic variance:** Single random seed → non-deterministic scores across runs. Addressed in evaluation by averaging over 5 repeated sampling runs per query; reported $\pm$ values reflect this.

---

### Stage 6: D2 Shape Descriptor

Characterizes global pairwise distance distribution.

$$\hat{d}_{ij} = \frac{\|p_i - p_j\|}{\delta}, \qquad F_{D2} = \text{histogram}(\hat{d}_{ij}), \quad \hat{d}_{ij} \in [0,1]$$

where $\delta = \sqrt{\Delta x^2 + \Delta y^2 + \Delta z^2}$ is the bounding-box diagonal.

- $K = 10^5$ random point pairs, area-weighted triangle sampling
- 64-bin histogram, L1-normalized
- $F_{D2} \in \mathbb{R}^{64}$

**What D2 captures:** Narrow peaked histogram → compact, near-spherical model. Broad flat histogram → elongated or irregular. Multi-modal → distinct sub-structures (flanged shaft, bladed rotor). Normalized by bounding-box diagonal → scale-invariant.

---

### Stage 7: Feature Fusion and Standardization

**Per-descriptor Z-score standardization** using database-wide statistics:
$$z = \frac{x - \mu}{\sigma}$$
where $\mu, \sigma$ computed across all database models for each descriptor independently.

**Concatenation:**
$$F = [F_\text{HOG},\ F_{D1},\ F_{D2}] \in \mathbb{R}^{5420}$$

| Descriptor | Dimension |
|------------|-----------|
| HOG | 5292 |
| D1 | 64 |
| D2 | 64 |
| **Fused** | **5420** |

**Complementarity rationale:**
- HOG: fine-grained local occupancy patterns and edge orientations (from MDOR density maps)
- D1: radial mass concentration — not captured by HOG or D2
- D2: global compactness, elongation, scale-invariant pairwise distances

D1 and D2 together add only 128 dimensions over HOG alone for a 20.5 P@5 point gain (71.00% → 91.50%), or $\approx 0.16$ P@5 points per added dimension — two orders of magnitude more efficient than Gabor ($\sim 0.001$ P@5/dim) or LBP ($\sim 0.0018$ P@5/dim).

---

### Stage 8: PCA Dimensionality Reduction

$$F_\text{PCA} = W^\top F$$

PCA trained on the database descriptor matrix. 95% variance retained → 86 components from 5420.

| Variance Retained | Components |
|-------------------|------------|
| 90% | 76 |
| 95% | 86 |
| 98% | 93 |
| 99% | 95 |

The explained-variance curve rises steeply over the first 20–30 components then flattens — the descriptor's variance is concentrated in a small subspace. $F_\text{PCA} \in \mathbb{R}^{86}$.

---

### Stage 9: FAISS Indexing and Retrieval

**Similarity metric:** Cosine similarity
$$\text{Sim}(F_q, F_d) = \frac{F_q \cdot F_d}{\|F_q\| \|F_d\|}$$

FAISS does not natively support cosine similarity → every PCA-compressed descriptor is L2-normalized first → inner-product search is mathematically equivalent.

**Index type:** `IndexFlatIP` (exact inner-product search, no approximation).

**Query complexity:** $O(N_\text{db} \cdot d_\text{PCA})$. At $N_\text{db} = 600$, $d_\text{PCA} = 86$ → sub-millisecond.

**No OOD rejection:** The system always returns top-K results even when no true match exists. False positives are not flagged. This is an open gap.

## Evaluation Protocol

**Leave-one-out:** Each model queried against remaining 599; relevance = same class. P@5 and P@10 averaged over **5 repeated D1/D2 sampling runs per query** to account for stochastic sampling variance. Reported $\pm$ values = standard deviation across 5 runs, aggregated over all 600 queries.

**P@10 ceiling:** Each class has 40 models. Leave-one-out pool = 39 relevant items. P@10 ceiling = 39/40 = **97.5%**, not 100%. All P@10 figures should be read against this ceiling.

**Determinism:** Every stage except D1/D2 point sampling is strictly deterministic for a given mesh. Standard deviations isolate stochastic sampling variance only.

## Results

### Main retrieval results

| Method | P@5 (%) | P@10 (%) |
|--------|---------|---------|
| D1 only | 58.20 ± 4.77 | 56.40 ± 2.63 |
| D2 only | 63.50 ± 4.90 | 56.55 ± 4.77 |
| HOG only | 71.00 ± 2.66 | 61.60 ± 3.96 |
| HOG + D1 | 76.90 ± 3.46 | 72.05 ± 2.90 |
| HOG + D2 | 81.50 ± 3.27 | 76.85 ± 3.54 |
| **HOG + D1 + D2** | **91.50 ± 3.49** | **83.25 ± 3.07** |
| HOG + Gabor | 93.60 | 86.10 |
| HOG + LBP | 96.60 | 90.00 |

HOG+Gabor and HOG+LBP are evaluated but not adopted as primary: +39.9% and +52.3% dimensionality over HOG+D1+D2, 2.3× and 2.8× slower extraction, and they are local texture descriptors computed from the same MDOR density maps as HOG — redundant refinements of the same occupancy signal rather than an orthogonal modality.

### Effect of slicing direction count

Sweep on HOG-only configuration:

| Directions | P@5 (%) | Avg. time per model (s) |
|-----------|---------|------------------------|
| 1 | 62.30 | 0.006 |
| 2 | 72.20 | 0.041 |
| 3 | 91.50 | 0.097 |
| 4 | 92.80 | 0.306 |
| 6 | 93.60 | 0.820 |
| 8 | 95.00 | 0.970 |
| 10 | 95.00 | 1.930 |
| 12 | 98.00 | — |

Three directions is the accuracy/cost knee: +29.2 P@5 points over one direction at $16\times$ the time. Going from 3 to 12 directions adds 6.5 P@5 points at $20\times$ the cost. Beyond 3 directions, additional views are non-axis-aligned combinations of the same three coordinate planes and re-express already-captured information.

### Effect of slice count N (HOG-only)

P@5 rises sharply from $N=20$ to $N=100$, flattens from $N=100$ onward. Peak at $N=140$ is within run-to-run standard deviation. $N=100$ selected as saturation point: slice spacing ($L_\text{max}/100$) and pixel pitch ($L_\text{max}/128$) are comparable — finer slicing cannot reveal detail the $128 \times 128$ density map cannot represent.

### Descriptor contribution analysis

Per-descriptor similarity decomposition for a query $q$ and database model $d$:

$$S_\text{HOG}(q,d) = \frac{F^{\text{HOG}}_q \cdot F^{\text{HOG}}_d}{\|F^{\text{HOG}}_q\| \|F^{\text{HOG}}_d\|}, \quad S_{D1}(q,d) = \frac{F^{D1}_q \cdot F^{D1}_d}{\|F^{D1}_q\| \|F^{D1}_d\|}, \quad S_{D2}(q,d) = \frac{F^{D2}_q \cdot F^{D2}_d}{\|F^{D2}_q\| \|F^{D2}_d\|}$$

Normalized contributions:
$$C_\text{HOG} = \frac{S_\text{HOG}}{S_\text{HOG} + S_{D1} + S_{D2}}, \quad C_{D1} = \frac{S_{D1}}{S_\text{HOG} + S_{D1} + S_{D2}}, \quad C_{D2} = \frac{S_{D2}}{S_\text{HOG} + S_{D1} + S_{D2}}$$

**Empirical contribution profiles by class type:**
- Flanged bearings, chain drives (complex local structure) → HOG contribution 55–70%
- Bushes, cylindrical pins (elongated, compact) → D2 contribution 30–45%
- Washers, clamps (flat, radially concentrated) → D1 contribution 25–35%

## Robustness

- **Mesh noise:** Tolerates up to 5% relative Gaussian noise with <5 P@5 point drop
- **Triangle reduction:** Tolerates up to 75% decimation with <5 P@5 point drop
- Robustness attributed to statistical nature of D1/D2 sampling and density-based MDOR — both are relatively insensitive to localized surface perturbations

## Known Failure Modes

### 1. TPMS lattice structures (documented)

Tested on 8 TPMS lattice models: Fischer-Koch S, Gyroid, I-WP, Diamond (2 instances each, matched unit-cell frequency and strut density).

- Fischer-Koch S query → retrieves Gyroid as best match
- I-WP query → retrieves Diamond as best match

**Root cause:** MDOR slice-density maps and D1/D2 histograms are statistical summaries of occupancy and periodicity, not topological encodings. Two TPMS families with similar porosity, strut thickness, and repeat frequency but different minimal-surface topology produce near-identical density and distance histograms. None of HOG, D1, or D2 encodes genus or connectivity.

**Resolution floor explanation:** TPMS strut thicknesses are often within a few multiples of $\delta_\text{pixel} = L_\text{max}/128$ relative to the overall bounding box. Fine topological distinctions are exactly the sub-pixel-scale detail this representation cannot resolve.

### 2. PCA alignment ambiguity (not yet fixed)

Near-symmetric objects with close eigenvalues → unstable axis assignment → descriptor flips on minor mesh perturbation. Affects MDOR consistency since slicing axes depend on PCA output.

### 3. Scale blindness (by design)

Normalization strips absolute size. No descriptor currently captures physical scale — a 5 mm fastener and a 500 mm flange with the same shape produce identical descriptors.

### 4. No OOD rejection

FAISS always returns top-K. No threshold to flag "no acceptable match found."

### 5. Sub-pixel features

Features smaller than $L_\text{max}/128$ (working floor: $L_\text{max}/128 \times 2$–$3$ due to HOG cell aggregation) are invisible to the pipeline. Not yet empirically validated with a feature-size sweep — derivation is resolution-based bound only.

## Open Directions Explicitly Named in Paper

These are from the conclusion — not yet implemented:

1. **Approximate nearest-neighbor indexing** (HNSW-based FAISS) for scaling beyond ~10K models
2. **Persistent homology / genus descriptors** for TPMS and topologically complex structures
3. **Adaptive MDOR** — variable slice density concentrated in geometrically complex regions
4. **Multi-resolution slicing** — recover fine detail lost at $128 \times 128$
5. **Descriptor weighting optimization** (training-free) — class-conditional contribution reweighting derived from Eq. 25 decomposition
6. **B-Rep / STEP format extension** — current pipeline is mesh-only
7. **Graph neural CAD retrieval** as learned complement to training-free baseline
8. **Assembly-level / manufacturing-aware similarity** — tolerances, material properties
9. **Large-scale evaluation** beyond 15 classes / 600 models
